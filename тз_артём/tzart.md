# Модель базы сервиса шаблонов документов

Сервис хранит каталог шаблонов документов (ODT и OTT) и историю их версий. Пользователь находит шаблон по названию или тексту, открывает актуальную версию или скачивает старую по номеру. В PostgreSQL хранятся карточки шаблонов, сведения о версиях и результат разбора файлов. Сами файлы лежат в отдельном хранилище, в базе только путь к ним. Схема: `template_catalog_final.drawio`.

## Таблица `template`

Одна строка на шаблон. Название и описание одинаковы для всех версий, поэтому хранятся здесь один раз.

| Поле | Тип и ограничения | Назначение |
|---|---|---|
| `template_id` | `varchar(64)`, первичный ключ, `check (template_id ~ '^[a-z0-9-]{3,64}$')` | имя шаблона латиницей, например `lease-contract`. Задаётся при создании и не меняется. Используется в адресах API и в пути к файлу. |
| `title` | `varchar(255) not null`, `check (trim(title) <> '')` | название для каталога, списка и поиска. Не может быть пустым или из одних пробелов. Можно изменить. |
| `description` | `text not null` | назначение шаблона. Можно изменить. |
| `created_at` | `timestamptz not null default current_timestamp` | когда создана карточка. |
| `created_by` | `text not null` | кто создал карточку. |
| `updated_at` | `timestamptz not null` | когда карточку меняли последний раз. При вставке равно `created_at`. |
| `updated_by` | `text not null` | кто менял карточку последним. При вставке равно `created_by`. |

Название и описание в ответах по любой версии берутся из карточки. После переименования все версии показываются с новым названием.

## Таблица `template_version`

Одна строка на версию. Первичный ключ — пара `(template_id, minor_version)`, `template_id` ссылается на `template`. У шаблона одна или несколько версий, каждая версия принадлежит одному шаблону.

| Поле | Тип и ограничения | Назначение |
|---|---|---|
| `template_id` | `varchar(64)`, часть первичного ключа и внешний ключ | к какому шаблону относится версия. |
| `minor_version` | `int`, часть первичного ключа, `check (minor_version >= 0)` | число после точки: в базе `3`, в API `1.3`. Число, а не строка, чтобы `1.10` шла после `1.9`. |
| `change_note` | `text`, может быть `null` | что изменилось в версии. |
| `file_format` | `varchar(3) not null`, `odt` или `ott` | формат, определённый по содержимому файла. |
| `file_sha256` | `varchar(64) not null`, 64 символа `0–9` и `a–f` | хеш файла: по нему ловится повторная загрузка и проверяется целостность файла в хранилище. |
| `size_in_bytes` | `int not null`, от 1 до 20 971 520 | размер файла, не больше 20 МБ. |
| `path_to_file` | `text`, генерируемая: `'templates/' \|\| template_id \|\| '/1.' \|\| minor_version::text \|\| '.' \|\| file_format` | путь в хранилище, например `templates/lease-contract/1.3.odt`. Считает база, вручную не записать. Уникален, потому что собран из первичного ключа. |
| `page_width_mm` | `numeric(6,1) not null`, больше 0 | ширина основной страницы из `styles.xml`. |
| `page_height_mm` | `numeric(6,1) not null`, больше 0 | высота основной страницы из `styles.xml`. |
| `page_format` | `varchar(6)`, генерируемая | `a0`–`a5` по сторонам листа с допуском 2 мм, иначе `custom`. |
| `orientation` | `varchar(9)`, генерируемая | `landscape`, если ширина больше высоты, иначе `portrait`. |
| `document_text` | `text not null` | текст из `content.xml` для поиска. Документ без текста хранит пустую строку. |
| `fields` | `jsonb not null default '[]'::jsonb`, `check (jsonb_typeof(fields) = 'array')` | поля подстановки из `content.xml`, например `[{"name": "fio", "type": "string"}]`. Хранятся и отдаются целиком. |
| `created_at` | `timestamptz not null default current_timestamp` | когда загружена версия. |
| `created_by` | `text not null` | кто загрузил версию. |
| `updated_at` | `timestamptz not null` | когда версию меняли последний раз. При вставке равно `created_at`. |
| `updated_by` | `text not null` | кто менял версию последним. При вставке равно `created_by`. |

## Поля аудита и изменения

Исполнитель приходит в заголовке `X-User-Login`. При вставке сервис записывает его и в `created_by`, и в `updated_by`, а в `created_at` и `updated_at` ставит одно время. Новая версия не меняет поля аудита карточки и старых версий.

Изменять можно немногое:

- в карточке `title` и `description`;
- в версии только `change_note`, например чтобы исправить опечатку в комментарии.

При изменении сервис пишет новые `updated_at` и `updated_by`, `created_*` не трогает. Файл версии, хеш, размер, лист, текст и поля не меняются никогда: другой файл — это новая версия. Удалять шаблоны и версии нельзя. Это закреплено правами роли, под которой сервис подключается к базе: ей разрешены `select` и `insert`, а `update` только на перечисленные колонки.

## Правила загрузки и чтения

1. Первая загрузка. Сервис проверяет файл и в одной транзакции создаёт карточку и версию `1.0`. Если `template_id` уже занят, загрузка отклоняется. Карточки без версии не бывает.

2. Формат файла. Определяется по содержимому, а не по расширению: файл открывается как zip, первая запись `mimetype` хранится без сжатия и указывает odt или ott, `content.xml`, `styles.xml` и `META-INF/manifest.xml` разбираются как XML. Расширение загруженного файла должно совпадать с форматом из `mimetype`. Результат записывается в `file_format`.

3. Размер листа. Ширина и высота основной страницы берутся из `styles.xml`, формат и ориентацию вычисляет база. Значения всегда соответствуют файлу. Они нужны системам, которые накладывают на документ штамп электронной подписи или рамку чертежа: на А4 книжном и А4 альбомном угол листа в разных местах. Если у новой версии лист отличается от последней больше чем на 2 мм, загрузка отклоняется, пока клиент явно не подтвердит смену листа.

4. Проверка повторов. Хеш нового файла сравнивается только с последней версией шаблона. Совпал — загрузка отклоняется, файл уже актуален. Совпал с одной из старых версий — это откат, создаётся новая версия. Например, в `1.4` ошибка, файл `1.3` загружают снова, и он становится `1.5`. Любое изменение файла, даже одна буква, даёт другой хеш и новую версию. Одинаковые файлы у разных шаблонов разрешены.

5. Новые версии. Сервис блокирует строку карточки (`select … for update`), чтобы две одновременные загрузки не получили один номер. Номер новой версии на единицу больше последнего. Сначала файл сохраняется в хранилище, потом в той же транзакции вставляется строка версии. Если хранилище недоступно, транзакция откатывается.

6. Актуальная версия. Это версия с наибольшим `minor_version`. Каталог показывает название из карточки и номер актуальной версии, старые версии открываются по номеру.

## Почему так

Название и описание зависят только от шаблона, поэтому лежат в `template` один раз. Всё, что относится к конкретной версии, лежит в `template_version`. Поля подстановки хранятся одним `jsonb`, потому что сервис получает и отдаёт их целиком. Путь к файлу, формат и ориентацию листа считает база, поэтому они всегда совпадают с остальными колонками.
