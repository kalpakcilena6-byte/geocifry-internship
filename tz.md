# модель базы сервиса шаблонов документов

сервис хранит каталог шаблонов и историю их редакций. пользователь находит шаблон по названию, открывает актуальную версию или скачивает конкретную старую редакцию. в postgresql хранятся карточки, сведения о версиях и результат разбора. байты файлов хранятся отдельно.

## таблица `template`

одна строка на шаблон. название и назначение карточки общие для всех версий, поэтому хранятся один раз. постоянный идентификатор используется в адресах api и связывает карточку с историей.

| поле | тип и ограничения | назначение |
|---|---|---|
| `template_id` | `varchar(64)`, первичный ключ, `not null` | постоянный строковый идентификатор. при первой загрузке его берём из запроса. |
| `title` | `varchar(200) not null` | понятное пользователю название для карточки, списка и поиска. при создании карточки название передаётся явно. |
| `description` | `text not null` | обязательное описание назначения всего шаблона. при первом создании его передают при заполнении карточки. |
| `created_at` | `timestamptz not null default current_timestamp` | время создания карточки. |
| `created_by` | `text not null` | идентификатор автора создания карточки. |
| `updated_at` | `timestamptz not null` | время последней записи карточки. при вставке равно `created_at`. |
| `updated_by` | `text not null` | идентификатор исполнителя последней записи карточки. при вставке равен `created_by`. |

при запросе конкретной версии сервис находит её по паре `(template_id, minor_version)`. если в ответе предусмотрен `title`, сервис берёт его из карточки по тому же `template_id`. в ответах по всем версиям одного шаблона отображается текущее название этой карточки.

## таблица `template_version`

одна строка на сохранённую редакцию. первичный ключ — пара `(template_id, minor_version)`. внешний ключ `template_id` ссылается на `template(template_id)`. у одного шаблона может быть несколько редакций, а каждая редакция относится к одному шаблону.

| поле | тип и ограничения | назначение |
|---|---|---|
| `template_id` | `varchar(64)`, часть первичного ключа и внешний ключ | определяет, к какой карточке относится редакция. |
| `minor_version` | `integer`, часть первичного ключа, `check (minor_version >= 0)` | номер после точки. в бд храним `0`, в api возвращаем `1.0`. |
| `created_at` | `timestamptz not null default current_timestamp` | время сохранения этой редакции. |
| `created_by` | `text not null` | идентификатор того, кто загрузил эту редакцию. |
| `updated_at` | `timestamptz not null` | время последней записи этой редакции. при вставке равно `created_at`. |
| `updated_by` | `text not null` | идентификатор исполнителя последней записи этой редакции. при вставке равен `created_by`. |
| `change_note` | `text`, допускает `null` | кратко описывает, что изменилось. в истории достаточно номера, даты и комментария. |
| `file_name` | `text not null`, расширение `.ott` или `.odt` | исходное имя для скачивания. |
| `file_sha256` | `varchar(64) not null`, 64 символа от `0` до `9` и от `a` до `f` | хеш байтов файла для поиска повторных загрузок. |
| `size_in_bytes` | `integer not null`, от 1 до 20 971 520 байт | фактический размер файла для проверки лимита в 20 миб и ответа api. |
| `path_to_file` | `text not null unique` | отдельный ключ редакции в хранилище. сервис генерирует его на основе идентификатора шаблона и номера редакции, независимо от исходного имени. |
| `page_format` | `text not null`, допустимы `a3`, `a4`, `a5`, по умолчанию `a4` | настройка формата страницы в описании версии. |
| `orientation` | `text not null`, допустимы `portrait` и `landscape`, по умолчанию `portrait` | настройка ориентации в описании версии. |
| `document_text` | `text not null` | результат извлечения текста. пустой текст сохраняется как пустая строка. |
| `fields` | `jsonb not null default '[]'::jsonb`, `check (jsonb_typeof(fields) = 'array')` | массив полей подстановки, который сервис получает от парсера и возвращает целиком. тип и обязательность каждого элемента проверяет сервис. |

## заполнение полей аудита

при первой загрузке сервис создаёт карточку и версию `1.0` в одной транзакции. в каждом запросе вставки он передаёт один и тот же идентификатор исполнителя в `created_by` и `updated_by`, а в `created_at` и `updated_at` записывает одно время. это делает код вставки. ограничение `not null` само значения между столбцами не переносит.

при вставке версии используем тот же принцип, в том числе при загрузке `1.1` и следующих редакций. добавление строки версии не обновляет поля аудита карточки или старых версий. при фактическом редактировании существующей строки сервис записывает новое время и исполнителя в `updated_at` и `updated_by`, а поля `created_*` сохраняет. изменение содержимого уже сохранённой редакции по-прежнему требует загрузки новой версии. если редактирование метаданных редакции не предусмотрено, её поля обновления остаются равными полям создания.

## правила загрузки и чтения

1. **первая загрузка.** сервис проверяет файл и сохраняет карточку и версию `1.0` в одной транзакции бд. внешний ключ проверяет наличие карточки у версии. наличие первой версии у новой карточки обеспечивает операция загрузки.
2. **формат файла.** сервис определяет формат по содержимому и проверяет совпадение с расширением. несовпадение приводит к отказу в загрузке. при таком правиле `source_format` получается из расширения в нижнем регистре, а в бд достаточно `file_name`. проверка имени в бд проверяет только расширение.
3. **настройки страницы.** формат и ориентация описывают версию целиком. они сами по себе не изменяют байты загруженного файла. в бд форматы страницы хранятся в нижнем регистре. если публичный api уже использует прописные обозначения формата страницы, сервис преобразует значение на границе api и бд, сохраняя действующий контракт.
4. **проверка повторов.** после подстановки настроек по умолчанию сервис ищет в истории совпадение по `(template_id, file_sha256, page_format, orientation)`. правило обеспечивает сервис: проверку и запись выполняют под блокировкой строки шаблона в одной транзакции. переименование файла или изменение комментария при тех же байтах и настройках не даёт новой версии. запись и путь существующей редакции сохраняются. совпадение с исторической редакцией не делает её актуальной. одинаковые байты для разных шаблонов разрешены.
5. **новые редакции.** изменения файла или сочетания настроек создают новую версию, если в истории ещё нет такой комбинации. сохранённые редакции доступны по номеру. при одновременных загрузках проверку повтора и назначение номера выполняем последовательно для одного шаблона. новую запись подтверждаем после сохранения файла. для каждой новой редакции создаём отдельный ключ хранения. `unique` на `path_to_file` сохраняется.
6. **актуальная версия.** это версия с наибольшим `minor_version` среди успешно сохранённых версий шаблона. каталог показывает название карточки и актуальную редакцию, а нужную старую версию пользователь открывает по её номеру.

## обоснование структуры

`template_id` определяет свойства карточки. сочетание `(template_id, minor_version)` определяет данные редакции. поэтому описание и название каталога хранятся один раз, а история хранит данные каждого сохранения. поля подстановки используются как единый результат парсинга редакции и хранятся в `jsonb`.
